Resultado: un calendario «AVIA Social · {{ workspace.name }}» en tu Google Calendar. Lo que programes o muevas en AVIA se reflejará allí. Tus eventos personales no se leen ni se importan.

1 · Abre el proyecto correcto

En Google Cloud, selecciona el proyecto de AVIA en la barra superior. Puedes usar el mismo proyecto y cliente OAuth de YouTube: Calendar requiere otra API, otro permiso y otra URL de retorno. No borres las credenciales ni las URL de YouTube.

2 · Habilita la API y añade el permiso

  1. Abre APIs y servicios → Biblioteca → Google Calendar API. Pulsa Habilitar. Si ves «Administrar», ya está habilitada.
  2. Ve a Google Auth Platform → Acceso a los datos (Data Access) → Agregar o quitar permisos.
  3. Si no lo encuentras en la lista, baja hasta Agrega permisos manualmente. Pega el valor completo de abajo, pulsa Agregar a la tabla, confirma que esté seleccionado y guarda.
https://www.googleapis.com/auth/calendar.app.created

No selecciones permisos de BigQuery ni acceso general a todos tus calendarios.

3 · Registra el retorno en el campo correcto

En Google Auth Platform → Clientes (Clients), abre el cliente web existente o crea uno de tipo Aplicación web llamado «AVIA Social · Calendar».

URI de redireccionamiento autorizados → Añadir URI

{{ calendar_callback }}

Pega aquí la URL completa, con /callback/ y barra final. Conserva las URI existentes y pulsa Guardar.

4 · Autoriza tu cuenta de prueba

Si la app está en Testing, ve a Audience (Público) → Test users → Add users y añade el correo que autorizará Calendar. Usa el mismo proyecto del cliente que acabas de configurar.

5 · Guarda aquí y conecta

Copia el Client ID y el Client secret de ese cliente. Si reutilizas el de YouTube, son sus mismos valores; no necesitas reemplazar la conexión de YouTube.

{% csrf_token %}

Después: Conectar Google Calendar → autorizar en Google → Crear calendario AVIA. Abre Google Calendar y marca el calendario de AVIA para verlo junto a los personales. Los cambios que hagas directamente en Google no reprograman AVIA.

Si aparece un error, encuentra aquí el siguiente paso

«Origen no válido… no debe contener una ruta»: pegaste el callback en Orígenes JavaScript. Muévelo a URI de redireccionamiento autorizados.

redirect_uri_mismatch: compara la URL completa del error con la de arriba. Deben coincidir dominio, ruta y barra final.

403 access_denied / solo testers: añade el correo exacto en Audience → Test users y comprueba que el Client ID del error pertenezca a ese proyecto.

El permiso no aparece: habilita Calendar API y usa Agrega permisos manualmente. Actualiza la consola si acabas de habilitar la API.

Se desconecta tras unos días: en Testing, los refresh tokens de estos permisos normalmente vencen a los 7 días. Reautoriza para continuar las pruebas y prepara los requisitos de producción para una conexión estable.
