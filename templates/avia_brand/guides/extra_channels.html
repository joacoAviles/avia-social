«Sin configurar» significa que faltan credenciales de la aplicación para esta modalidad. No significa que tu cuenta LinkedIn haya sido rechazada. Guardar credenciales habilita la autorización; los permisos los concede LinkedIn.

1 · Abre tu aplicación LinkedIn

En LinkedIn Developers → My apps, crea o selecciona la aplicación. Completa su información y la verificación que solicite LinkedIn.

2 · Habilita los productos adecuados

{% if card.platform == 'linkedin_personal' %}

Para el perfil personal, prepara Sign In with LinkedIn using OpenID Connect y Share on LinkedIn. Este conector utiliza openid, profile, email y w_member_social. No ofrece estadísticas del perfil personal ni mensajes privados.

{% else %}

Para páginas de empresa necesitas acceso a Community Management API y los permisos de organización concedidos a tu app. El inicio de sesión personal por sí solo no habilita páginas. La persona que autoriza debe tener el rol adecuado en las páginas.

Revisa en Auth los permisos disponibles, incluidos w_organization_social, r_organization_social y rw_organization_admin. Si LinkedIn no los concede, completa su proceso de acceso; no se soluciona repitiendo el login.

{% endif %}

3 · Copia el retorno exacto

En Auth → OAuth 2.0 settings → Authorized redirect URLs, añade la dirección de retorno mostrada debajo. Personal y Company tienen retornos distintos. Si usas la misma app para ambos, registra ambos retornos y guarda sus credenciales en cada modalidad; no hace falta crear dos apps si la misma tiene los productos necesarios.

4 · Guarda y autoriza

Copia Client ID y Client Secret desde Auth. Guarda aquí y vuelve a «Conectar {{ card.title }}». Inicia sesión y autoriza. Company permite seleccionar las páginas que la API devuelva.

Si sigue apareciendo sin configurar o falla el login

Comprueba que guardaste ambos campos en esta organización y en la modalidad correcta. Las variables de entorno completas tienen prioridad sobre el formulario: si la URL de autorización usa otro cliente, el administrador debe revisar esa configuración. No compartas secretos.

Un error de scope indica productos o permisos faltantes en LinkedIn. Un error de redirect URI indica que el retorno no coincide. Ninguno se arregla borrando tus otras conexiones.

{% elif card.platform == 'x' %}

1 · Prepara X Developer

Abre X Developer Console. Verifica que tu acceso a la API permita las operaciones que necesitas y revisa sus condiciones de uso y facturación.

2 · Activa OAuth 2.0

En la app configura User authentication con tipo Web App (cliente confidencial). Registra el retorno exacto mostrado debajo. Copia el OAuth 2.0 Client ID y Client Secret; no uses el bearer token de aplicación ni las claves OAuth 1.0a.

3 · Conecta tu cuenta

Guarda y pulsa Conectar X / Twitter. La autorización usa PKCE y solicita tweet.read, tweet.write, users.read y offline.access. Esta versión admite solo texto; no imágenes, videos, mensajes ni estadísticas. No se ha comprobado una publicación real desde esta instalación.

{% elif card.platform == 'reddit' %}

1 · Comprueba el acceso aprobado

Consulta Reddit Data API. Una cuenta Reddit o una app Devvit no equivalen a autorización para una integración externa. Configura este conector solo con acceso aprobado para tu uso.

2 · Registra la aplicación web

Usa el cliente OAuth de tipo web autorizado por Reddit y registra el callback exacto de abajo. El conector solicita identity y submit con autorización permanente para renovar el acceso.

3 · Elige el destino

Indica la comunidad sin «r/» y el usuario desarrollador sin «u/». La comunidad es el destino predeterminado para las cuentas Reddit de esta organización. Cambiarla afecta publicaciones futuras; revísala antes de programar.

Solo texto: el título del editor se usa como título del post; si no existe, se usa la primera línea. El título no puede superar 300 caracteres. Comunidades que exigen flair u otros campos pueden rechazar el envío; esos campos no están implementados. No se han probado envíos reales.

{% endif %}
