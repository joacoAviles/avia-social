Primero comprueba qué flujo permite tu app de Meta.

Si ves «Unified Login» y «Token de usuario del sistema (SUAT)», no uses el formulario del flujo anterior. Esta versión todavía no completa la selección de activos y el ciclo de tokens de Unified Login. El asistente rechazará esa modalidad sin cambiar las conexiones existentes.

{% if not request.is_secure %}

Estás usando HTTP. La pantalla de Meta que compartiste exige una URL HTTPS. Configura el dominio HTTPS real de AVIA y abre el asistente desde él antes de copiar el callback. Registrar una URL distinta en Meta no cambia la que envía AVIA. Abre «Dominio HTTPS con Cloudflare» en esta guía para prepararlo.

{% endif %}

Un portafolio comercial administra la propiedad de la app; no es una página de Facebook. Si Meta exige portafolio, selecciona el existente con control total o completa su aprobación. No crees otro para intentar evitar el requisito.

{% if card.platform == 'instagram_login' %}

1 · Prepara Instagram directo

Necesitas una cuenta profesional de Instagram (empresa o creador). No necesitas una página de Facebook ni conectar otra red a AVIA.

  1. Si tu cuenta es personal, cambia a una cuenta profesional desde los ajustes de Instagram.
  2. El administrador entra en Meta for Developers → Mis aplicaciones y crea o selecciona la aplicación. La cuenta de desarrollador de Meta es una configuración administrativa; no vincula una página de Facebook a tu Instagram.
  3. Solo si Meta permite el flujo anterior, configura Instagram API con Instagram Login. Si indica que no está disponible para apps nuevas y exige Unified Login, este conector no es compatible con esa configuración; no pruebes intercambiando App IDs.
  4. Registra la dirección de retorno que mostramos debajo. Usa el dominio HTTPS de esta instalación.
  5. Copia el Instagram App ID y su secreto correspondiente a este formulario y guarda. No uses las credenciales de otra aplicación ni tokens copiados de Instagram.

2 · Conecta Instagram

Pulsa «Conectar Instagram directo», inicia sesión en Instagram y acepta los permisos. Al regresar revisa el nombre y el estado de la cuenta. No hace falta completar Facebook, Google ni GitHub primero.

{% else %}

1 · Prepara Facebook

Conecta páginas sobre las que tienes permisos de administración. Esta opción no publica en perfiles personales ni ofrece conexión de grupos.

  1. El administrador abre Meta for Developers → Mis aplicaciones y crea o selecciona la aplicación.
  2. Configura el inicio de sesión de Facebook y el acceso a páginas para las funciones que usarás. El conector actual usa un token de usuario para descubrir páginas. Si usas Login for Business, copia su Configuration ID (config_id) al formulario. No selecciones SUAT para este flujo.
  3. Registra la dirección de retorno que aparece debajo en la configuración OAuth. Debe coincidir exactamente con tu instalación HTTPS.
  4. Copia el App ID y App Secret desde Configuración de la app → Básica. El config_id pertenece a Login for Business → Configuraciones, y no es el App ID. Guarda aquí los tres valores cuando corresponda.

2 · Selecciona tus páginas

Pulsa «Conectar Facebook», inicia sesión y concede acceso a las páginas que quieras usar. Completa la selección que muestre el flujo y revisa las cuentas registradas al volver. No necesitas conectar Instagram primero.

{% endif %}

El administrador prepara la aplicación una vez; cada usuario autoriza su cuenta. Para pruebas usa cuentas y roles autorizados por Meta. Para usuarios externos, completa la revisión y los requisitos de acceso que Meta solicite para los permisos elegidos. Una autorización no confirma que todas las funciones de publicación o mensajes estén aprobadas.

Qué revisar antes de autorizar

  1. Meta App ID, secreto y config_id deben pertenecer a la misma app y configuración.
  2. La cuenta de prueba debe tener los roles y acceso a los activos requeridos. Revisa solicitudes pendientes del portafolio.
  3. Publicar en páginas requiere permisos como pages_manage_posts; listar páginas, pages_show_list. No añadas permisos publicitarios solo porque la pantalla los ofrece.
  4. La URL OAuth es para iniciar sesión. La URL de webhook es otra configuración: no pegues el callback OAuth en webhooks.
  5. Una conexión guardada no acredita revisión de Meta, mensajes ni publicación real. Comprueba esas funciones por separado.
